Guia rapida de aprendizaje

SP Local IA por dentro

Una explicacion corta, intuitiva y divertida de como esta montada la aplicacion web local que acabas de probar.

Idea central

Piensa en el proyecto como una academia digital con tres equipos: la pantalla que ves, el cerebro que decide y la caja fuerte donde se guardan los datos.

1. El mapa del edificio

frontend

Es el mostrador de la academia. Aqui viven las pantallas, formularios, panel del alumno, admin, temario, supuestos, examenes, soporte y cuenta.

backend

Es la direccion del centro. Valida usuarios, sesiones, permisos, planes, intentos, correcciones, soporte, pagos simulados e IA.

shared

Es el diccionario comun. Guarda contratos Zod para que frontend y backend hablen el mismo idioma y no se pasen datos raros.

infra

Scripts para levantar entorno local, WSL, variables y pruebas.

docs

Documentacion tecnica: arquitectura, seguridad, IA, billing y despliegue.

tests

Pruebas de navegador que comprueban que los flujos importantes funcionan.

2. Como viaja una accion

Alumno

Pulsa, responde, estudia o envia un supuesto.

>

API Nest

Comprueba sesion, permisos, plan y reglas del negocio.

>

Datos

PostgreSQL guarda lo serio; Redis acelera sesiones, limites y colas.

Truco mental: la pantalla pide, el backend decide, la base de datos recuerda.

3. Funcionalidad principal

Alumno

  • Registro, verificacion por correo, login y cuenta.
  • Planes de prueba sin cobro real.
  • Temario, supuestos practicos, examenes y progreso.
  • Banco de errores, manual, tutor IA y soporte.

Admin y soporte

  • Gestion de usuarios, roles, suspensiones y auditoria.
  • Revision de contenido, fuentes y versiones.
  • Mensajes de soporte con notas privadas.
  • Planes, suscripciones y derechos manuales.

4. Organizacion del backend

Modulos

Cada area vive en su modulo: auth, exams, progress, support, admin, ai, manual y mas.

Prisma

schema.prisma define las tablas. Las migraciones crean la base y el seed mete contenido demo.

Trabajos

BullMQ permite corregir tareas en segundo plano, recuperar trabajos pendientes y no bloquear la web.

5. Organizacion del frontend

app

Rutas de Next: publicas, privadas, admin y paginas concretas.

features

Piezas grandes por funcionalidad: auth, casos, examenes, progreso, billing.

components

Componentes reutilizables: layout, UI comun y bloques de evaluacion.

7. Mini juego mental: quien hace que?

Si algo se ve mal...

Mira primero frontend/src/app, features o components. Es probable que sea pantalla, estilos o datos pintados.

Si algo se guarda mal...

Mira backend/src/modules y despues Prisma. Es probable que sea una regla, permiso, validacion o escritura en base de datos.

Si frontend y backend no se entienden...

Mira shared/src/schemas. Es el contrato entre ambos.

Si quieres saber si funciona...

Ejecuta pnpm test, pnpm build y pnpm test:e2e.

8. Lo importante que debes recordar

Estado actual

Es una version local funcional: puedes registrarte, estudiar, practicar, hacer examenes, ver progreso, usar soporte y probar planes sin cobro.

Limites sanos

La IA y los pagos estan simulados para la demo local. Para produccion faltan claves reales, revision juridica, textos legales definitivos y despliegue publico.
